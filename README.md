# servicenow-client-script-ui-policy
Implementation of Client Script and UI Policy on the ServiceNow Incident form to dynamically control field behaviour and improve incident management.
ServiceNow Client Script & UI Policy – Incident Management

📌 Project Overview

This project demonstrates the implementation of Client Scripts and UI Policies in ServiceNow Incident Management.

The project focuses on customizing the Incident form and dynamically controlling field behaviour based on user actions and predefined conditions.

🎯 Objectives

- Implement Client Scripts in ServiceNow
- Configure UI Policies for the Incident form
- Dynamically control field behaviour
- Improve form usability and data validation
- Understand client-side customization in ServiceNow

🛠️ Technologies Used

- ServiceNow
- Incident Management
- Client Scripts
- UI Policies
- JavaScript

⚙️ Features

Client Script

Client Scripts are used to execute JavaScript on the client side and control the behaviour of ServiceNow forms.

They can be triggered during:

- Form loading
- Field value changes
- Form submission

UI Policy

UI Policies dynamically control the behaviour of fields based on specified conditions.

They can make fields:

- Mandatory
- Visible
- Read-only

🏗️ Project Workflow

1. Open the Incident form in ServiceNow.
2. Configure the required Client Script.
3. Define the appropriate trigger and condition.
4. Add the required JavaScript logic.
5. Create a UI Policy for the Incident table.
6. Define the condition for the UI Policy.
7. Configure the required UI Policy Actions.
8. Test the behaviour on the Incident form.
9. Verify that the fields respond correctly to the configured conditions.

🧪 Testing

The Incident form was tested under different conditions to verify that:

- The Client Script executes correctly.
- UI Policy conditions are applied correctly.
- Fields change their behaviour as configured.
- Invalid form submissions are handled appropriately.
